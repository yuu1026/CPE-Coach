# 逐步核對教學

目前完整路徑支援 UVa 10041 Vito's family 與 UVa 10055 Hashmat，並綁定專案題目敘述版本。其他 47 題仍是一般助理問答，沒有因此取得完整路徑驗證。沒有更換模型、重新微調或啟用新的 Adapter。

## 使用方式

在這兩題說「我沒有想法，請引導我」、「給我輸入骨架」或「請教我下一步」。已有程式時會辨識目前版本，保留學生的名稱與可用結構，一次只推進一個局部步驟。沒有一、二、三級提示選單，也不需按「繼續修改」才能接續：直接回答聊天中的問題即可。

可插入詢問中位數、排序、絕對值及 Hashmat 型別等已整理觀念。若要一般問答，可以說「退出引導」或「先不要測驗」；後續不會自動再啟用核對路徑。說「恢復引導」或「重新開始」可重新建立核對進度，聊天紀錄與編輯器內容保留。明確要求完整解答仍使用原本的完整解答流程，不以檢查問題阻擋。

## 如何避免一步錯就卡住

1. 起步例子與輸入骨架來自專案教學卡。骨架核心留 TODO，先通過 C++17 編譯，不宣稱已通過題目測資。
2. 將目前原碼辨識為讀輸入、排序、選中位數、累加距離與輸出等步驟。單一 vector、逐項讀入迴圈及案例 while 的位置要能核對；不猜複雜控制流程或任意 AST。
3. 模型只提出當輪的局部計畫，候選的 C++ token 與註解須符合核對步驟。理由使用已整理的教學事實，不直接發布模型自由生成的診斷文字。
4. 模型計畫不合格或連線失敗時，使用同一步驟的系統替代計畫。回覆明確標示來源，保留模型候選及原因供評估；這不是模型獨立成功。
5. 暫存副本要通過編譯、原先通過案例不可退步，再加一個概念小實驗。排序等前置步驟允許總通過數不變，但清楚標示整題仍未完成；不使用增加測資通過數作為唯一進度指標。
6. 前端沿用原本的版本／測資核對及套用按鈕。未自動覆寫學生編輯器。

## 學生理解與程式正確分開

理解問題由應用程式核對具體數值作答，不由模型自行評分。說「我懂了」不會直接新增通過紀錄；答錯時先說明，再換一組數字，避免只重抄剛揭露的答案。作答紀錄保留問題 ID、變體、答案及對錯，代表觀察到這次作答，不能證明掌握整個概念。

這是有範圍的數值／順序題核對，不是完整自然語言或程式理解評量。複雜說明、未辨識到的答案形式可繼續澄清，不能用任意文字關鍵字當成答對。

程式完成主要步驟後，另外執行：

- Vito：24 組額外地址，由 Python 枚舉可住位置計算最小總和，與學生 C++ 的中位數做法分開。
- Hashmat：40 組額外整數對，包括零、交換順序與 2^32 範圍。

每組額外輸入合併在一個 judge 案例中，不能把 1/1 寫成 24 或 40 個獨立 judge 工作。檢查快取同時綁定目前程式及完整測資 SHA-256，程式或測資改變就重新驗證。先前完成狀態不能直接套到新版本。

## 完成的意義

`tests_and_checks_complete` 只表示這條支援路徑的程式測試與指定數值作答完成。`independent_rebuild` 仍為 `not_assessed`；沒有宣稱真人已能獨立重寫、跨題應用，或已通過官方評測。完成標記仍由使用者自行設定。

需要進一步找真正初學者，觀察其不看原碼重寫及處理不同題目的表現，才可評估獨立教學能力。把系統輔助完成、模型獨立提出正確修改、學生真正學會分開記錄，不能相互替代。

## 邊界

辨識器不是完整 C++ AST。多個容器、原始字串、複雜巨集、不同迴圈／輸入結構或未涵蓋的解法可能超出範圍；這時保留原碼、說明不能安全定位，允許退出引導繼續問答。不能把「未辨識」說成學生程式一定有錯。

概念小實驗是教學卡中公式／API 的獨立示範，不是任意學生程式語意的證明。主要可信證據仍是實際候選編譯、前後測資、來源範圍核對與最後額外測試。

狀態保存在既有提交 `messages` JSON，沒有新增資料庫遷移。實測資料與限制見 [核對教學實測報告](../training/reports/guided-learning-review.md)。
