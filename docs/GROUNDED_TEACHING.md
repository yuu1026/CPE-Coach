# 問答內容核對與多輪數值狀態

這次調整回答流程，使用相同 Gemma 3 4B IT 基礎權重；沒有重新微調。目標是減少不相關題目干擾、保存使用者已提供的數值，以及攔下部分已知 C++ 解釋錯誤。

## 問題分類與模型輸入

`coach/learning_context.py` 判斷問題是否為一般 C++ 概念。這類問題由 `coach/model_prompt.py` 提供當前程式、最新問題及相關知識卡，不附上 Vito 等題目背景、舊診斷與不相關的模型回答。

題意、骨架、完整解答與原碼修正仍使用題目相關流程。這些分類是內部資料選擇方式，不需要使用者選提示等級。目前採用可測試的詞彙規則，尚非任意語句皆能準確理解。

## 多輪地址狀態

目前針對 UVa 10041 的小型手算例子支援：

1. 從使用者明確列出的地址保存 `learning_state.addresses`，不從助理的回答猜地址。
2. 追問只改住址時，沿用同一對話中最近的明確地址，重新計算距離。
3. 新地址覆蓋舊地址；無法處理的地址格式、非法數值或明確重置不沿用舊地址。
4. 只沿用地址，不沿用先前住址與計算結果；地址來源標為本輪或先前使用者訊息。
5. 狀態保存在每輪訊息 JSON；即使模型上下文只保留六輪，後端仍能從同分支使用者問題恢復狀態。清除聊天或另開分支不應混入其他對話。

目前支援明確列出 2–20 個、範圍為 1–29999 的地址。單一地址、代詞指向不明、同時比較多個住址等情形，窄型計算器可能不產生結果，不能宣稱它涵蓋所有題目數學。

## C++ 知識核對

`coach/cpp_knowledge.py` 包含專案編寫的三張卡片：整數除法、乘法前提升型別、一般區域變數的作用域與生命週期。卡片用於本輪檢索與提示，不是新模型權重。

回覆先經窄型規則檢查。候選不符合已知條件或被截斷時，最多重新生成一次；仍不符合則明確顯示「系統 C++ 知識核對」，並保存兩個候選與拒絕原因。網站將此來源記為 `knowledge`，不能計入模型獨立答對的比例。

概念示範不會自動套用到學生程式；需要修改時仍走副本編譯、測資比對與防退步流程。這三張卡片與詞彙檢查都不構成完整的 C++ 語意驗證器。

## Docker 與權限

本輪已透過 Codex 的命令提權審查成功存取 Docker Desktop 的本機管線。使用者只需讓 Docker Desktop 保持啟動；若 Codex 顯示授權提示，可核准該次本機測試命令。網站由使用者正常開啟的終端機啟動時，會使用該使用者的 Windows 權限。

六個 Docker 探針的結果見 `training/reports/grounded-v32-cpp-probes.json`：整數除法、轉型前除法、外部副本、乘法前提升及負數除法符合預期；區塊外直接使用變數正確地編譯失敗。未執行懸空參考或有號整數溢位等未定義行為。
