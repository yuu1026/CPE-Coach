# 本地回覆耗時與進度

網站、模型仍使用原有啟動指令與 Gemma 3 4B IT 權重。啟動網站前執行 `python manage.py migrate`；原本 PowerShell 啟動腳本會自動執行資料庫更新。本次新增 `Submission.performance`，保存耗時、模型呼叫次數、輸入／輸出 token 數及重試原因，不保存額外的提示文字或憑證。

## 流程

瀏覽器送出問題 → Django 驗證表單與對話歸屬 → 建立一次提交，立即回傳 202 → 本機工作執行緒處理 → 瀏覽器讀取該筆紀錄的進度 → 檢查完成後進入完整回覆頁。

- 不再用整頁原生 POST 等待模型。沒有 JavaScript 時仍保留原有同步表單流程。
- 相同提交 UUID 不啟動第二個工作。單一網站程序同時只接受一個背景教學工作，忙碌時保留尚未送出的問題，不排無限隊列。
- 重新整理可用同一分頁的 sessionStorage 恢復進度，不重送模型；接受提交的 token 同時連結瀏覽器草稿，保留等待期間的編輯。
- 模型橋接以 NDJSON 串流產生文字，網站只顯示階段、秒數與已生成字數。原始模型文字及程式不作未驗證預覽。生成、品質檢查與必要的編譯／測資驗證完成後才交付答案。
- 完整程式或局部修改仍經原有驗證；未通過的候選不開放套用。一般提示連續兩次截斷時也不交付不完整答案。
- 本機橋接仍接受 `stream:false`。外部模型 URL 預設使用原有非串流介面；可用環境變數 `MODEL_STREAM=0` 停用本機串流，需重啟網站。

## 可重用與不可省略的工作

已有測試結果只有在程式、完整測資、比對方式與判題政策的 SHA-256 完全相同，且結果完整時，才作局部修改的基準。這只省略原程式的重測；模型候選仍需編譯、逐案比較及防退步檢查。改了任何程式或測資就重新測基準。

結構化稽核歷史保留原有六輪；一般模型傳輸最多帶最近兩個完整對話回合，目前完整學生程式不裁切，既有學習進度資料繼續提供。沒有將舊模型的說法擅自摘要成已證明的學生理解。

曾嘗試大幅縮短提示，但固定題目出現更長回答、截斷及語意退步，因此最終保留原有提示內容。一般提示輸出上限 256 token；局部修改維持 512，骨架／完整答案維持 1024。上限不代表會生成這麼多，也不能將碰到上限當作已完成回答。

## 量測

`coach/performance.py` 使用每次請求獨立的 context，記錄累計階段秒數、基準與候選驗證、模型網路呼叫、token 數與重試原因。模型的 `first_text_seconds` 是後端收到／產生第一段文字的時間，不等於使用者看到已驗證答案的時間。

重現固定模擬資料的命令（需模型與 Docker Desktop 啟動）：

```powershell
python tools/benchmark_latency.py --variant local-check --rebuild --report training/reports/local-latency-check.json
```

逐題比較與失敗紀錄見 [實測報告](../training/reports/latency-review.md)。不要將不同時間的機器負載、暖機、回答長度或後端呼叫測試與瀏覽器整體等待混為同一速度指標。

## 部署範圍

這是單機開發網站的背景工作，不是持久任務佇列。重啟網站程序可能中斷工作；頁面會保留紀錄並提供恢復入口，重新整理不會擅自重新生成。長時間等待後可查看該筆紀錄；若程序確實中斷，應重新送出新請求。正式多人部署應使用持久工作佇列及明確的中斷／逾時回收機制。

串流中斷時不交付半份回答；模型生成工作會在連線結束後請求停止，GPU 鎖維持到工作實際結束，避免同時啟動兩次生成。
