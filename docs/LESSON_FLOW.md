# 自然需求與局部教學流程

本次修改優先處理 v34 模擬學習發現的需求誤判、單行程式定位與骨架洩漏問題。預設仍是 Gemma 3 4B IT 基礎模型，沒有重新微調或自動採用舊實驗 Adapter。

## 當輪需求優先

`coach/conversation_policy.py` 區分實際請求與限制：

| 說法 | 處理 |
|---|---|
| 我已貼上骨架，下一步只教一個局部修改 | 接續目前程式，不再索取骨架 |
| 請修改輸出，不要整份重寫 | 允許局部修正 |
| 你上一個候選把 while 放錯，請保留我的 main 修正 | 修正當前原碼，不把失敗候選當作原碼事實 |
| 請解釋，不要修改 | 保持說明 |
| 請再給一個骨架 | 真正的新骨架請求 |

這仍是可測試的自然語句規則，並不保證能理解所有同義句。使用者無須選提示等級，且可明確要求完整答案。

## 用來源片段定位

`coach/code_units.py` 從目前原碼建立 U 標記：

- statement：一段敘述，例如變數宣告或輸出。
- expression：賦值右側或輸出運算元，例如 `first-second`。
- include：已有標頭的位置，可在函式外加入必要標頭。
- block_end：具有簡短原碼 context 的區塊結尾，可在輸入迴圈結束後插入步驟。

模型只需選片段並提供替換內容，不必重寫整行 main。定位使用原始字元偏移，保留學生排版；套用仍核對完整原版本，避免蓋掉新編輯。多個相同片段可依 U 標記分開定位，不再宣稱每個顯示片段都是唯一字串。

這是有範圍限制的詞法定位，不是完整 C++ AST。原始字串、巨集續行、複雜或損壞語法不一定有足夠片段。舊的精確 before/after 與 line_id 介面保留相容；不能因為找到片段就認定修改正確。

`coach/local_revision.py` 仍負責暫存副本、編譯、實測、防退步、重疊與修改量限制。未通過者不交付，編輯器也不自動覆寫。

若模型選了外層敘述，卻提供包住原運算式的完整運算式，系統只在唯一子運算式可精確對應時協助定位。例如將 `abs(first-second)` 對應到輸出中的 `first-second`，不改寫替換內容；有多個候選或夾帶其他敘述就拒絕。這是系統協助，回覆及來源 `model_projection` 會明確標示，不能算作模型自行正確定位。

新增標準標頭使用獨立 `header` 操作，系統將標頭放在函式外。只接受白名單標頭及嚴格等價格式，不將任意文字修成 C++。使用者明確要求本輪只加標頭時，不允許順便修改運算；此類步驟標記 `dependency_only`，即使可編譯也不宣稱演算法已有進步。

## 學習進度

`coach/lesson_progress.py` 記錄：目前程式雜湊、看得到的輸入／輸出／排序／for 特徵、學生自述已理解的內容、最近未交付次數、本輪目標及測試狀態。

這不是掌握程度評分，也不是完整的程式語意分析。含有 sort 不代表排序位置正確，學生說懂了也不代表已驗證理解。狀態寫入每輪原有訊息 JSON，提供模型參考，不需資料庫遷移。原碼與當輪實測結果仍優先。

## 骨架與教學內容檢查

骨架預設只搭輸入與流程：

- 核心要有真正的 TODO 註解，放在字串或回覆文字中的 TODO 不算。
- 不接受已啟用的排序、距離計算、累加或答案輸出。
- 不把完整解法藏在可直接啟用的註解裡。
- 攔下常見的案例迴圈內提前 return。

實作是保守的輸入骨架規則，不是完整演算法偵測器，可能限制某些進階骨架寫法。完整解答請求使用原本的編譯與測資流程，不套用骨架限制。

文字理由仍需要獨立判讀。編譯與測資通過不能證明「原因」正確，這輪實測仍有相關失敗，因此不宣稱已具備可靠獨立教學能力。

## 驗證與使用

200 項 Django 測試及前端草稿、Enter／輸入法、測試分流、清除聊天檢查通過；另以 v34 的真實失敗紀錄重播，五個需求／骨架案例已正確路由或攔下。資料庫遷移檢查沒有變更。

實際模型與 Docker 的比較見 [局部教學流程實測報告](../training/reports/lesson-flow-review.md)，包含 v35 至 v41 成功、被攔下與尚未完成的案例，不把工具或測試通過當成學生學會。

停止 Django 後，使用原本的 `啟動網站-真實模型.ps1 -BaseModel` 重啟，瀏覽器 Ctrl+F5 即可。模型權重與 Docker 映像不需重建；模型服務與 Docker Desktop 保持運作。
