# 局部教學流程改進與真實模型複驗

整理日期：2026-11-17。最終提示版本：`cpe-coach-v41-lessons`。

結論：局部修改定位與測試防退步有所改善，但仍未達到可靠、獨立引導初學者完成程式的標準。正確修改、理由正確、回覆完整及學生理解是分開的評估項目；不能以其中一項代替其他項目。

## 本次修改

- 以當輪需求區分「已貼上骨架」與「要求新骨架」，「不要整份重寫」仍可要求局部修改；候選錯誤不能當作學生原碼的錯誤。
- 從原碼標出敘述、運算式與區塊結尾，避免將壓成同一行的 main 整行換掉。這是詞法定位，並非完整 C++ AST。
- 新增白名單標頭操作，系統負責放到函式外；明確只加標頭的請求不得混入演算法修改。準備依賴只標記 `dependency_only`，不宣稱解題有進步。
- 模型誤選外層敘述時，只針對唯一、保留原運算元的完整包裝運算式協助定位。替換內容保持模型原文，另編譯與測試；來源標為 `model_projection`，文字也揭露系統協助。
- 記錄可觀察程式特徵、學生自述、本輪目標與最近未交付次數，提供下一輪參考。這不是掌握程度評分，沒有新增資料庫欄位。
- 將輸入骨架與完整解答分開驗證，攔下假 TODO、藏在註解的解法、核心計算與案例迴圈內提前 return。骨架規則刻意保守，不能視為一般程式語意證明。

使用的仍是本地 Gemma 3 4B IT 基礎模型；本輪沒有微調、修改權重或採用舊 Adapter。技術說明見 [教學流程](../../docs/LESSON_FLOW.md)。

## 實驗方式與限制

由助理模擬學生，直接呼叫正式後端、真實本地模型 HTTP 與 Docker 判題。不是瀏覽器視覺測試，也不是真實初學者研究。只採用實際交付的骨架或已驗證候選，不自行補正解。每份試驗最多五次提問。

各版本的 JSON 保存本輪問題、模型原始回覆、送入模型的內容與編譯／測試結果。版本間不合併計算成功率；改完後端後另開報告，不把不同版本的中途成功串成一次完整學習成功。

JSON 的 `commit` 是執行當下既有提交 `838e79b`，修改當時尚未提交；`prompt_version` 與 `backend_sha256` 才是當次工作樹識別。最終三份 v41 報告使用相同後端雜湊 `72bfca8a1031a7391e79f453ba609b57b7648584eee807820b1fcbe068430925`。

## 最終 v41 結果

| 情境 | 實測結果 | 判讀 |
|---|---|---|
| UVa 10055 Hashmat，修正學生的 `first-second` | 1/3 → 3/3；另外 40 組整數輸入全部相符 | 修改可用，但靠系統協助定位；理由仍錯誤，不算教學成功 |
| UVa 10041 Vito，從平均數選址程式要求局部修正 | 候選使用不存在的 vector 元素 `second`，後續候選又含彎引號 JSON；未交付修改，原程式保留 | 防護有效，模型仍無法完成這一步 |
| Vito，空白程式起步 | 用 1、2、3 說明總距離 3、2、3，算術正確；最後提問被截斷，`truncated=true`，仍被交付 | 不完整回覆仍是已知缺陷，不算完成教學 |

原始資料：[Hashmat](lesson-v41-hashmat.json)、[Vito](lesson-v41-vito.json)、[空白起步](lesson-v41-blank.json)。額外 40 組輸入包在一次 judge 案例中，因此報表顯示 1/1，不能寫成 40 個獨立 judge 案例或官方 AC。

Hashmat 的錯誤理由是「long long 型別可能無法正確表示負數」。實際上 `long long` 可以表示負數；本題需要絕對差，是因為距離不能為負數。這個錯誤說明仍通過目前流程，證明編譯與測資檢查無法驗證教學理由。實測生成的程式也依賴現有編譯環境解析 `abs`，不能用這批通過結果證明所有編譯環境的標頭可攜性。

## 自動化檢查

- `python manage.py test --noinput`：200 項測試全部通過，其中本輪新增 32 項。
- `node tools/test-workspace.cjs`：草稿、筆記與題目篩選通過。
- `node tools/test-workbench-events.cjs`：Enter／輸入法、測試與詢問分流、清除聊天通過。
- `python manage.py makemigrations --check --dry-run`：沒有遷移變更。
- `git diff --check`：沒有空白錯誤。
- [五筆舊失敗案例重播](lesson-v36-regression.json)：意圖路由或骨架拒絕符合預期；這不是五筆新的模型生成成功。

自動化測試大多使用固定資料與替身以驗證流程契約。真實模型的生成品質以以上實驗另行判讀；不宣稱 200 項測試代表 200 次成功教學。

## 尚未達標的項目

文字解釋錯誤、Vito 多步驟修改失敗、模型 JSON／C++ API 不可靠，以及被截斷的一般對話仍可能交付，都尚未解決。骨架攔截也只是避免交付不合格內容，並不代表模型已能提供合格骨架。下一輪品質提升應用固定未見題目與真實初學者複驗，並將「解釋正確、步驟可用、回覆完整、學生能獨立重做」分開評估；現有紀錄不能作為已具備獨立教學能力的證據。
