# 獨立教學能力實測結果（2026-11-16）

**結論：仍未達到穩定、可靠的獨立教學標準。** 在排版清楚的簡單程式上，有成功引導修正並正確回答理解追問的案例；完整學習路徑仍會遭遇錯誤解釋、任務分類誤判與無法交付修改。

- 後端 SHA-256：`01b35a43d401734a33c775c58ab622eef202e765ab47f9cc6626a9adc3017005`。每輪驗證一致，測試期間未修改應用程式或權重。

- 三條主要路徑，加一條事後追加的排版對照，共 **14 個使用者問題、23 次真實模型生成**。
- 模擬者只採用實際交付的骨架或精確的已驗證候選；四條路徑的程式變更來源均已逐輪檢查，不由評估者補正解。
- 這是開發者助理自評與模擬學習，不是真實學生研究、教師盲評、封存測試集或全部 49 題的能力統計。

## 發現的具體問題

### 1. 釐清矛盾時仍會誤導

空白起步第一輪列出三個地址 `[1,2,3]`，卻寫「親戚數量 2」。學生指出矛盾後，模型沒有正確承認範例數量寫錯，反而說「親戚指的是地址，而不是人」，又把不完整的 `3 2` 當成例子。

距離手算本身部分正確，不足以抵銷這個輸入概念錯誤。對初學者而言，這會干擾後續讀取人數與地址數量的實作。

### 2. 修正定位高度依賴排版

Hashmat 的單行 main 原本可編譯。模型知道應取絕對差，但多次把那一整行替換成獨立 while 或 cout，刪掉函式結構，Docker 因而拒絕。

追加多行對照前已確認兩份初始程式的 C++ 符號序列相同，只有空白、縮排與換行不同。多行版本第一輪就完成修改並通過 3/3，後續 40 組也通過。這是探索性對照，不能用成功對照取代原本失敗的單行路徑。

### 3. 系統會誤解使用者的限制語句

- 使用者描述「模型把 while 搬到函式外」，希望修正目前程式；系統卻選了概念問答，模型錯稱原程式的 while 就在函式外，甚至建議 cout 搭配 `%lld`。
- 使用者說「不要改寫整份程式」，意思是要局部修正；系統可能將它解讀成完全不允許修改，導致無法走已驗證的局部修改流程。
- 最後一句「我已貼上你給的骨架，下一步只教一個局部修改」，仍因包含「骨架」被判成 scaffold，沒有辨識當輪真正需求。

### 4. 骨架檢查仍可能放行完整答案

模型第四輪的骨架已包含排序及註解中的整題演算法，違背「只寫輸入、核心留空」的需求。第五輪更直接給完整可執行答案，只留下幾個 TODO 註解，便通過目前的骨架編譯檢查。

模擬學生原樣採用這份交付，確實通過 3/3 與 24 組額外輸入；但這只能證明收到的完整程式可用。它不是學生依局部提示自行補齊程式，也不能證明學生理解中位數。

### 5. 防退步有效，但未保證持續進展

Vito 原程式每輪都可編譯、維持 1/3。系統攔下不能編譯、沒有實質變更與造成原通過案例失敗的候選，沒有覆寫原碼。這是有效的保護，但三輪後仍無可採用修改，不能視為教學成功。

## 工具輔助與模型能力

主要回覆均有本專案整理的題意重點；部分 Vito 請求有計算核對。Hashmat 的錯誤補救曾進入 C++ 知識卡流程。每輪的 support 與 source 已記錄，因此不能把這些結果稱為無任何外部依據的裸模型能力。

本次沒有使用預寫的課程步驟替換來完成路徑，也沒有將題庫完整答案查表當成學生學會。成功的 Hashmat 多行案例是模型實際提出局部修改、Docker 驗證、原樣套用，再進行理解追問。

## 後續優先順序

1. 修正自然需求分類：分辨「提及先前骨架」與「現在索取骨架」，以及「不要整份重寫」與「不要修改」。
2. 局部修改定位以語法結構或可驗證的運算式片段為單位，減少對一行一個敘述的依賴。
3. 骨架需真正留下核心空缺，不能只因有 TODO 註解就認定尚未提供完整答案。
4. 以新的未見學習路徑再測，而不是只調整本輪問法直到通過；之後再邀請真實初學者與教師驗證。
