# 核對教學路徑：程式完成、作答確認與復原

日期：2026-11-17。最終提示版本：`cpe-coach-v47-guided`。

結論：在兩題已整理的教學路徑內，系統能從空白骨架或可辨識的學生程式，接續局部步驟、糾正數值作答，最後通過程式與指定理解檢查。模型候選失敗不再直接結束這些路徑，而是明確標示後改用經驗證的系統步驟。這是混合系統的進步，沒有證明本地模型已能獨立教學，也沒有證明真人能不看原碼重寫。

完整路徑僅支援 UVa 10041 Vito 與 UVa 10055 Hashmat；其他 47 題仍為一般問答。沒有訓練、更換模型或修改 Gemma 3 4B IT 權重。

## 修改

- 記錄這個分支的檢查 ID、數字變體、學生作答、對錯及待確認項目，不把「我懂了」當作通過。
- 答錯後先糾正，再使用新數字確認；作答正確後在同一則回覆接續下一步。
- 起步例子與可編譯輸入骨架使用已整理教學卡。骨架不含核心演算法。
- 根據目前學生原碼建立排序、選中位數、距離累加、輸出或絕對差等小步驟，保留名稱及其他原始 token。
- 模型取得已核對的局部計畫，輸出候選。程式 token 或註解超出該步驟即拒絕；文字理由由教學卡提供，模型原始理由只保留供審查。
- 模型未交付可用計畫時，系統使用同一步驟的替代計畫並揭露來源。候選仍要經 Docker 編譯、無退步檢查及概念示範；不能把系統替代算成模型獨立成功。
- 排序等必要前置步驟允許總通過數維持不變，明確標示整題未完成。概念示範並非任意學生程式的語意證明。
- 完成主要程式後，另跑獨立計算預期值的額外測資，以及新的數值應用問題。程式／測資版本改變就重新驗證，不沿用舊完成狀態。
- 可退出、暫停測驗、重新開始或恢復引導；明確要求完整答案仍使用既有完整解答流程。

技術及使用方式見 [逐步核對教學](../../docs/GUIDED_LEARNING.md)。

## 從網站實際走完一次

[網站紀錄](guided-v47-ui.json) 僅匯出本次合成資料 #194–#207，沒有帳號識別或憑證。過程：

1. 編輯器空白，要求小例子。系統問地址1、2、3住在1的總距離。
2. 學生回答4，正確指出應為3，改問地址2、4、9住在4的總距離。
3. 學生只說「我懂了」，通過紀錄仍為空，沒有直接跳到下一步。
4. 回答7後取得編譯通過、核心留白的輸入骨架；貼上頁面顯示的排版版本。
5. 依序取得排序、中位數、距離累加及輸出，每次僅按「套用已驗證修改」再測試，未自行補程式。
6. 測試紀錄 #199／#201／#203 均為0/3，直到輸出完成 #205 才為3/3。前置步驟沒有被冒稱整題成功。
7. 回答輸出順序7、0後，#206 另跑24組地址案例；再以未示範的3、8、14詢問最小距離總和。
8. 回答11後，#207 才標記 `tests_and_checks_complete`，同時明說獨立重寫尚未驗證。

逐步核對每個已交付候選與下一次測試原碼的 C++ token 均相同。骨架僅經頁面既有的排版處理，不含評估者獨立補解。四個修改中，排序與中位數使用模型候選，距離及輸出使用已標示的系統替代；整個流程有10次提問、4次前端程式測試。

這條網站流程在開發期間開始，#194–#198 為v46，#199以後為v47。過程發現舊排序文案對空白草稿提到不存在的「平均數選址」，已在v47改成只描述當輪排序，並加入回歸測試；原始舊訊息保留。凍結v47的完整 CLI 重跑另列於上表，沒有把開發中的混合版本冒稱為一次全程凍結實驗。

## 仍未證明的能力

這些是助理模擬，不是真人教學研究。數值作答答對不等於能寫出新的程式；本輪沒有用評估者自己重寫正解，來宣稱學生已獨立完成。`independent_rebuild` 維持 `not_assessed`。

辨識範圍集中在兩題的特定輸入結構與單一 vector／兩數差寫法。C陣列、複雜控制流程、不同解法、語法損壞等不一定能安全轉換；未知情況保留程式並說明限制。其他47題未取得這套完整路徑的驗證。

下一個實際標準應是真正初學者在不看原碼時重寫、處理新題與解釋自己的修改。現階段可以主張「兩題的系統輔助教學流程已完成模擬驗證」，不能主張「本地模型已可靠獨立教學」或「49題皆已驗證」。
