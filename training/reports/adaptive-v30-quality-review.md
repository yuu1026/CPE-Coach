# 真實 Gemma 回答品質複驗（2026-11-16）

## 方法

模型健康檢查回傳 `gemma-3-4b-it`、4096 context、NF4。透過網站目前的 `build_messages` 與 `generate_hint` 呼叫真正的 `/api/chat`，保留每次原始生成、重試、最終交付及拒絕原因。觀測包裝只記錄真正呼叫，未提供替代答案。

測試期間沒有修改回答規則、模型權重、使用者紀錄或原始題庫。以下是本次助理逐題判讀，不是外部教師評分，也不代表整體題庫正確率。

## 結果

## 系統檢查仍存在的缺口

1. 格式與引用檢查會放行錯誤的 C++ 語意解釋。
2. 計算工具只從最新問題抽取地址；省略既有地址的追問沒有取得同一份結構化資料，模型會混入舊住址。
3. 程式修改候選可能不保留使用者明確指定的變數；目前尚無這項完整的契約檢查。
4. 題目背景可能干擾一般 C++ 問答，例如把 total 誤解成親戚人數。

## 限制與測試資料修正

Docker CLI 回報 `permission denied ... dockerDesktopLinuxEngine`；執行環境拒絕提權，具名管線也無法用權限工具表示。本輪沒有取得任何新的編譯／執行成功證據。`adaptive-v30-cpp-probes.json` 中五項都是環境錯誤，不能當成 C++ 規則的實測佐證。

第一版 student-repair 測試草稿的換行字元有額外跳脫，意外成為多字元常數。已修正腳本，另存重試於 `adaptive-v30-quality-student-corrected.json`；原始紀錄保留，不以第一版作為乾淨的單一「平均數錯誤」案例。

原始七個請求總計八次生成（作用域重試一次），總耗時約 164.68 秒。修正測試草稿後再提出一次請求，耗時 37.67 秒；總計八個請求、九次真實生成。這次重試另列，不混入首輪統計。

## 結論

真實模型可連線且能產生繁體中文；自然需求辨識已有運作，但回答內容與連續追問仍不可靠。現有防護尚未攔下多個錯誤解釋，不能宣稱達到獨立教學標準。

優先改善方向是保存多輪題目數值狀態、將一般 C++ 概念問題與不相關題目背景分開，以及增加語意反例驗證。完成後應保留本輪案例作回歸，另增加未見問法作獨立評估。
