# 網站實際操作：模擬初學者教學評估

日期：2026-11-17。測試版本：`75b383a` / `cpe-coach-v41-lessons`。

判斷：網站已有局部教學價值，Hashmat 可以完成「測試失敗 → 局部修正 → 套用重測 → 解釋 → 糾正誤解」。但 Vito 的空白起步與已有錯誤程式兩條路線都中斷，因此目前適合有基礎者作為輔助，不能宣稱能可靠地獨立帶初學者完成題目。

這次從網站介面選題、輸入訊息、按 Enter、編輯 C++、執行測試及套用修改。使用已登入的本機測試帳號與真實 Gemma 3 4B IT，沒有用直接呼叫後端的方式代替學生操作。資料庫僅唯讀查詢本次產生的紀錄，用於補充耗時、模式及保存回覆；不修改生成結果。模型健康檢查為 ready、NF4、4096 context。

## 評估標準

將能否回答、針對學生原碼修改、說明是否正確、能否糾正誤解及推進下一步分開判斷。測資通過只證明本次輸入輸出相符，不代表學生理解或所有輸入正確。這是助理模擬，不是真實初學者研究，也未覆蓋全部 49 題。

## 情境 A：Vito 空白起步

學生自述只會 cin、cout、for、vector，請求小例子並且一次只問一個問題。紀錄 #179 的回覆卻另引入 `addresses={1,2,3}` 與 `relatives={1,2}`，兩組資料的關係不清楚，最後要求用一個數字說明距離，沒有指定要算哪兩個位置。能發起對話，但起步引導不夠精確。

學生接著自行作答「1 和 2 距離為 1；三位住 1、2、3，住 2 總距離為 2」，要求先提供讀輸入的骨架。#181 顯示泛用的模型連線／回應失敗，沒有交付骨架。學生縮小需求重試 #182，約 120 秒後仍顯示相同失敗；這條學習路線停在空白程式，沒有由評估者補骨架。

首次送出期間，瀏覽器觀測逾時；為恢復觀測另開分頁，產生了同義起步請求 #180。其回覆使用 1、2、3 例子並請學生選最小總距離，較清楚。這是測試操作造成的重複起點，不計成一次新學習成功，也沒有將兩條分支合併；主要流程為 #179 → #181 → #182。

## 情境 B：Hashmat 已有錯誤程式

初始學生程式用 `long long` 讀到 EOF，但直接輸出 `first-second`。它是測試情境的原始錯誤程式，並非評估者在對話中補出的修正。

1. 在聊天框保留尚未送出的測試文字，再按「執行測試」。#183 為 test、問題欄空白、模式 judge，沒有呼叫模型；對話框的草稿保留，測資 1/3 通過，清楚顯示 `3 8` 實際輸出 `-5`。
2. 學生要求保留變數、不整份重寫，只修改錯誤片段。#184 交付把 cout 運算式改成 `abs(first-second)` 的局部修改。理由只有「學生計算錯誤導致輸出結果錯誤，需要修正計算式」，沒有解釋距離與絕對值的關係。
3. 在網頁點「套用已驗證修改」，再點「執行測試」。#185 實際通過 3/3，沒有獨立補正程式。
4. 學生說測資通過但仍不懂 abs，要求依目前程式以 first=3、second=8 逐步說明，不再改程式。#186 正確回答 `abs(3-8)` → `abs(-5)` → 5，並問 `abs(x)` 代表什麼意思。這一輪有具體教學價值，且承接了學生程式。
5. 學生故意表達常見誤解：「abs 是相反數，所以 abs(5)=-5、abs(-5)=5」。#188 明確指出不正確，解釋絕對值是到零的距離，兩者都是 5，非負數不會被改成負數；接著再次確認定義。這是有效糾錯，沒有迎合學生。但確認方式仍偏向重述定義，尚未測試學生在新題獨立應用。

## 情境 C：Vito 已有平均數程式

這是與空白起步分開的獨立情境。初始學生原碼讀入所有地址，用 `sum/count` 選住址，再累加絕對距離。#187 從介面執行測試為 1/3，範例輸出 131，預期為 99。

學生要求依目前原碼只教下一步，保留程式、不直接給完整答案。#189 最後只顯示泛用的連線／回應失敗，沒有可套用修改或有效提示，停在原來的 1/3。沒有把先前其他版本曾經 2/3 的結果合併進本輪，也沒有替模型補出排序或中位數修正。

## 網頁體驗問題

- 後端記錄顯示起步 #179 約 69 秒、局部修改 #184 約 73 秒、觀念說明 #186 約 106 秒。耗時包含網站整個處理流程，不是純 token 生成速度。#180 與 #179 可能重疊，不能用這兩筆估算單一請求的純推論性能。
- 糾正誤解 #188 約 111 秒。這幾次成功回覆仍有很長等待，不宜只以「請求最後完成」評估教學體驗。
- #183、#185、#187 剛完成測試，尚未再次編輯程式，就顯示「已修改，請重新測試」。#184 同時顯示沿用 #183 的完全相同版本測試與需要重測。已確認畫面矛盾，尚未定位根因。
- 骨架失敗的網站訊息只有「請確認模型服務設定」，無法由畫面區分逾時、生成問題或內容驗證問題。本輪不憑泛用錯誤猜測模型的具體候選。
- Enter 可送出，完成後輸入框清空；測試與對話分開，局部修改需按鈕確認套用，均實際操作通過。

本輪僅測試與保存報告，沒有修改後端、前端或模型權重；未清除既有聊天、完成標記或使用者資料。

## 可追溯紀錄與後續優先順序

[本輪網站紀錄 JSON](ui-v41-records.json) 僅包含這次助理輸入的模擬資料，不包含帳號識別、Cookie 或憑證。它保存網站持久化的問題、原碼、回覆、測試及請求；未取得的失敗模型原始候選不作重建。三個情境合計七次教學提問、三次程式測試；另有前述一筆恢復觀測時的重複起步請求，不混入主要流程。未以這個小樣本計算通用教學成功率。

可見文字快照只移除每行結尾空白；JSON 中的程式與回覆保持網站所存原文，截圖未修改。

優先改善：

1. 先解決骨架與 Vito 原碼提問的失敗，讓學生能取得經驗證、足以繼續的下一步。只保留原碼不能算教學完成。
2. 縮短生成／驗證等待，提供可辨識的處理進度及可恢復的錯誤原因；不同故障不要全部要求使用者檢查模型設定。
3. 修正測試結果過期的誤報，避免剛測完又被要求重測。
4. 局部修改第一次交付就應連結錯誤輸入、原因及修改；理解確認改用新的小例子或讓學生自己預測結果，補足目前重述定義的限制。

以上是本次實測所得的改善項目，尚未在本輪實作。沒有獨立重做／跨題遷移測試，不能將模擬學生收到正確說明直接當成真人已學會。
