# 問答內容改善與真實模型複驗（2026-11-16）

## 本輪實作

- 一般 C++ 概念問題改用精簡輸入，不再帶入無關的 Vito 題意、歷史診斷或助理錯誤回答。
- 加入三張專案 C++ 知識卡：整數除法、乘法前轉型、區域變數作用域與生命週期。模型輸出經已知失敗規則檢查，最多重試一次；仍不合格時以明確標示的知識卡接手，保存候選與拒絕原因。
- 從同一分支的使用者問題保存地址狀態，追問改住址時重新計算；不把助理猜測的地址當事實，也不沿用上一輪住址與結果。
- 網頁新增「C++ 知識核對」來源標示。知識卡、計算工具與模型生成的成果分開記錄。

原始模型維持 Gemma 3 4B IT、NF4、4096 context。沿用 tokenizer 的 apply_chat_template；確認本機模板包含 system 處理。這輪未訓練或切換 Adapter。

## 驗證方法

真實呼叫本機 /api/chat；觀測包裝僅記錄真正生成，不提供替代答案。使用 Docker 編譯執行，沒有自行修改模型候選來使其通過，也未改動使用者帳號與學習紀錄。以下判讀由本次助理完成，不是獨立教師評分。

程式回歸 168 項通過；前端草稿、筆記、篩選、Enter／輸入法、測試與聊天分離、清除聊天檢查通過。六個短 C++ 探針都符合預期，包含應該編譯失敗的作用域案例；沒有執行懸空參考或有號溢位。

v33 的 scope 與其餘六項分開執行，應用程式核心相同；v34 只擴充副本與負數除法的檢查。七項主案例共十次真實生成。它們是開發回歸案例，不能當成未見題的泛化成績。

|---|---|---|

## 轉移案例：仍有重大錯誤

先測 v33 的不同數字／命名，再修正已發現的副本失效與向下取整說法，執行 v34 複驗。這些是追加開發案例，不是永久封存、從未看過的測試集。

| v34 案例 | 判讀 | 證據 |
|---|---|---|
| local 複製到 saved | 不通過 | 已不再說副本變回 0，卻錯稱 saved 是函式外的靜態變數。結論雖是副本仍有效，理由仍錯誤，現有檢查未攔下。 |
| -7/2 存入 double | 通過本案例 | 重試後正確解釋先整數除法，再轉為 -3.0，未再說成向下取整或 double 無法保存小數。 |
| 地址 4、9、30，住在 14 | 通過本案例 | 正確算出 10+5+16=31。 |
| 同地址改住在 9 | 不通過 | 26 的數值正確，但模型誤稱 14 不在原地址中，所以距離無法定義；實際住在 14 的距離仍為 31。不能只因算出 26 就判定回答正確。 |

v34 轉移複驗四次請求、六次生成。兩項仍有語意錯誤。因此這輪能確認局部改善與部分攔截有效，尚不能宣稱可靠獨立教學。窄型規則可回歸已知錯誤，但不能證明任意解釋正確。

## 重現

模型與 Docker 啟動後，以可存取 Docker 的終端機執行。輸出檔必須尚不存在：

```powershell
python tools/verify_cpp_knowledge.py --output training/reports/new-cpp-probes.json
python tools/review_adaptive_quality_live.py --output training/reports/new-main.json
python tools/review_adaptive_quality_live.py --transfer --output training/reports/new-transfer.json
```

逐次生成可能有差異；重新檢查原始答案與測資，不只看 delivered。下一輪應處理住址選擇範圍的錯誤解釋、儲存期判斷，以及保留學生指定命名的要求，再建立新的封存測試題。
