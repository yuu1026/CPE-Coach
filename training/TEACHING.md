# 本地模型是否真的能引導寫程式？

最新的逐輪跟隨模擬見 [LEARNER_SIMULATION.md](LEARNER_SIMULATION.md)：讓初學者依模型回覆修改自己的平均數草稿，12次詢問後仍未完成；保留實際退步與錯誤候選，未以作者手改正解取代失敗。

v23 更新與完整驗收門檻請見 [ACCEPTANCE.md](ACCEPTANCE.md)。已知 Vito 四步系統輔助流程可完成並通過84組枚舉對照案例；四輪都有題庫課程替代，因此不計為模型獨立完成。以下九輪 v18 評估為歷史結果，不能當成 v23 成績。

**目前尚未達到「可靠、獨立引導初學者完成程式」的標準。** 網站與判題能正常運作，模型能給出部分有效提示，但不能把成功回覆、程式測試通過或低訓練 loss 當作教學能力已合格。

這次使用實際運行的 Gemma 3 4B IT 基礎模型、Django HTTP/CSRF 流程與 Docker，以 UVa 10041 驗證。未呼叫付費 GPT API，未使用真實學生資料。未通過評估的 v6/v7 微調權重沒有啟用。

## 九輪逐步教學

固定情境依序測試：沒有想法、理解目標、猜平均數、偶數中位數、已有輸入草稿、漏排序、漏絕對值、程式已通過測試，以及換新數字手算。測試開始前就要求每輪至少自評4/5、無重大內容錯誤，且必須能推進程式。

| 版本 | 回覆成功／9 | 內容發現 |
|---|---:|---|
| v15 | 9/9 | 把一維地址當二維座標、否認中位數保證最小、沿用舊錯誤 |
| v16 | 7/9 | 排序與abs定位改善；仍錯怪正確加總，部分合法問答被引用檢查誤擋 |
| v17 | 7/9 | 能確認131與999，但又把103/3寫成33.666；轉成程式及確認結果仍有阻礙 |
| v18 | 8/9 | 結果確認改善；偶數案例算錯、int除法解釋錯，程式下一步未成功送達 |

「回覆成功」只表示網站取得完整回覆，**不是教學正確率**。同一腳本已用來改進提示與工具，因此後面的結果是已知案例回歸，不能冒充未見題目的盲測。

最新一輪完整腳本的 GPT/Codex 逐例自評平均 **2.44/5**，僅 **4/9** 輪達4分，仍有重大錯誤。這不是獨立教師評分，更不是實際學生的學習成效。固定腳本的學生程式預先編寫，不能因為最後那份程式過測，就說是模型把學生教會。

## 只跟隨實際提示補程式

為避免測試者暗中補答案，另做動態模擬：學習者原本只會 cin/cout、for 與 vector，先提供只讀取地址的草稿；每次程式變更都記錄上一則模型提示作依據。

1. 原本的純模型回覆不是跳到錯誤的相鄰距離算法，就是重貼整份草稿，被教學層級檢查拒絕。
2. 加入可辨識草稿的課程步驟與局部新增顯示後，模型成功教出排序與 `<algorithm>`。此處有課程與後處理輔助，不是模型獨立推導的證據。
3. 下一則卻直接給出使用 `home` 的距離迴圈，沒有先宣告它。測試者照實貼上，沒有自己補中位數，Docker 確認編譯失敗。
4. 把編譯訊息交回模型後，候選仍建議固定 `home=0` 並重貼main，未能完成有效補救。流程在此停止，**沒有產生可提交的最終程式**。

[完整動態紀錄、每次修改依據與原始候選](reports/adaptive-tutoring-vito-20261116.json) · [引用檢查失敗的候選調查](reports/tutoring-read-code-trace-v17.json)

最後的 [v22 單步 HTTP 整合檢查](reports/tutoring-step-integration-v22-20261116.json)確認局部排序顯示已生效，但尾段又要求找「最接近尚未選定home的位置」，仍屬循環說明，沒有計為語意品質通過。最新完整九輪報告是v18；後續是針對已知問題的定點修正與檢查，沒有宣稱v22已完整通過九輪。

不能把「攔住錯誤提示」算成「成功教會學生」。目前證據只支持：系統有局部輔助能力，還不能取代可靠的程式教師。

## 已實作的改善與界線

- 分開「從想法開始」「概念／手算」「新增一小段」「檢查目前錯誤」「只確認當次測試」，減少每輪都反問或硬找錯。
- 題意重點補上一維地址、正確中位數性質與常見誤解，並綁定題目摘要。不能把這些已提供的知識算成模型自行學會。
- 小型計算工具核對明確輸入的地址、位置、總距離與平均值，避免把已算對的數值說成錯誤。僅處理可辨識、合法且不歧義的小型數字列表，不執行學生程式，也不是通用語意證明器。
- 對可辨識的單一 `vector<int>` 草稿，課程工具一次建議一個步驟；不支援的語法退回一般模型，不聲稱能解析任意C++。
- 模型若只是重貼原程式並加入本輪已知小片段，只有在原token保留、所有新增token與課程片段／必要標頭一致，而且沒有其他程式區塊時，才只顯示局部新增。改演算法、刪除原碼或加入其他片段不會被這樣處理。這是呈現與課程約束，不是神經模型遵循教學規則的證明。
- 已知的一維題意矛盾、結果矛盾、未要求就貼main、尚未宣告home卻跳到距離計算等問題會觸發最多一次修正；這些是有限的回歸檢查，仍不能攔住所有內容錯誤。
- 完整解答另經隔離 Docker 編譯與題庫測資比對，未通過就不當作有效完整解答。這不驗證文字解釋一定正確，也不代表官方AC。

[完整答案驗證紀錄](reports/runtime-validation-v14.json)證明一份新生成程式通過三組題庫測資，但說明仍把平均數與中位數理由混淆。這正說明「程式能跑」和「能教懂」必須分開評估。

## 重現

先啟動 Docker、模型與網站，在專案根目錄執行：

```powershell
python tools/test_tutoring_live.py --output training/reports/tutoring-new-run.json
```

會建立並清除臨時帳號，執行真實模型請求，輸出原始回答與測資結果。版本化舊報告不覆寫。

動態跟隨測試可從 [起始請求](examples/tutoring-start.json)複製一份自己的JSON開始：

```powershell
python tools/tutoring_step.py --request training/examples/tutoring-start.json --report training/reports/adaptive-new-run.json
```

之後每次只依實際回覆修改 request，並寫下 rationale；`action=test` 才會將那份模擬學生程式送 Docker。不得偷偷補上正確解法後宣稱引導成功。

目前應把專案定位為**有工具把關的實驗性 CPE 助手**，而非已證實能自主教學的老師。要主張教學有效，還需不同題型、未用於調整的對話與真實學生前後測；目前沒有這些證據。
