# 局部修改驗證與防退步（v29）

本輪改善「模型依學生原碼修改，卻讓程式退步」；沒有宣稱模型已具備可靠的獨立教學能力，也未更換權重。

## 使用方式

在原本程式與聊天框提出局部修正要求。模型提出計畫後，系統先在副本驗證；合格才顯示實際原片段、替換片段、通過數變化，以及「套用已驗證修改」「還原套用前程式」。不自動覆寫編輯器，不自動標記題目完成，也不把副本結果當作編輯器已測試。

套用前會核對原碼與當時的自訂測資選擇；使用者已編輯或改測資就不覆寫，需重新詢問。還原只在編輯器仍與剛套用的候選一致時執行，避免蓋掉套用後的其他編輯。套用前版本亦保留於該次提交紀錄，聊天清除後移除候選操作。

## 驗證流程

1. 以目前完整原碼、本輪問題、題意重點與實際測試證據為準。修改請求不再送出先前助理的未驗證結論。
2. 先在受限Docker跑原碼，建立本次測資的實際基線。若全部通過，直接確認本次測資通過並保留，不硬找錯或呼叫模型改寫。這不等於官方AC。
3. 模型回傳短JSON修改計畫，選擇系統為當前原碼標定的L1、L2等行標記並提供替換內容。系統由標記取得真正的原片段，不讓模型憑空補註解、猜省略號。也保留逐字且唯一before/after片段格式。
4. 核對範圍、重疊、無變更與修改大小，在暫存字串套用；最多4處、原／新片段合計32行，原碼上限12000字元。原提交不變。
5. 編譯並執行同一批測資，包含已啟用的自訂測資。**逐一核對原本通過的案例，不只看總通過數**。相同通過數但換成其他案例通過，仍會判定退步。
6. 原本可編譯而候選不能編譯、原先通過案例失敗、修錯任務未增加通過案例、定位失敗、截斷或格式錯誤均退回，最多重試一次。未完成草稿的「下一步」可接受仍未增加測資通過數，但必須編譯且不損失原通過案例；畫面會如實顯示0/3等數值，不當作完成解題。
7. 合格候選與原碼、兩份測試結果、雜湊、修改與重試紀錄留在提交的JSON稽核資料。畫面的套用資料只包含合格候選與原碼，不夾帶被拒絕候選。失敗時僅顯示拒絕原因，原程式保留。

概念／手算與修改分開處理：概念回覆可引用原碼，但新C++程式區塊必須走修改驗證；可辨識的新片段若走到普通問答路徑會被攔下重試。這不是通用自然語言語意證明器，仍無法保證每句旁白或行內說法正確。完整修正版針對現有程式時，Docker不可用或輸出截斷也不再交付未驗證程式。

## 實際驗證

| 測試 | 結果與解讀 |
| --- | --- |
| 同一行換同一行 | 拒絕，避免無效修改 |
| 平均數改取中間元素、尚未排序 | 實際1/3→2/3，保留原通過案例，可作部分進步；不是整題完成 |
| 把選址搬到讀取前 | 實際2/3→0/3，拒絕交付 |
| 把sort放到main開頭 | 實際編譯失敗，拒絕交付 |
| 正確的排序與中位數局部修補 | 實際1/3→3/3，允許；這項使用固定測試計畫，不是模型自行答對的成績 |

實際神經模型請求並沒有成功交付：第一次因連線逾時停止；重試的模型捏造原片段／註解而被拒絕；v29已能選到行標記，但把`houses.begin() + r / 2`當成int，兩次候選均被C++編譯攔下。因此本輪證據是防護可拒絕這些錯改，不能報成模型修改成功率5/5。報告保留當時完整候選供稽核；現行網站失敗訊息已不附上被拒絕的修改計畫。

[控制器與實際Docker整合](reports/local-revision-workflow-v29.json)使用**明確標示的固定模型JSON，沒有呼叫神經模型**，確認原碼不變、包含自訂測資共4組、候選4/4通過、套用／還原控制出現，且後續「執行測試」不再呼叫模型。臨時帳號與相關提交已清除。這是功能整合驗證，不是教學能力評分或瀏覽器視覺QA。

141項Django測試、兩組Node互動測試及差異檢查通過，涵蓋範圍重疊、無效修改、同通過數仍退步、服務不可用、截斷、稽核／畫面隔離、帳號隔離、自訂測資、過期候選不覆寫、套用後新編輯不被還原覆蓋等。

## 服務與資料

清理了先前測試留下的重複模型程序，保留單一基礎模型。模型啟動改為先獨佔保留連接埠，再載入GPU權重。[實際第二次啟動](reports/model-single-instance-v29.json)在0.27秒因連接埠占用退出，沒有開始載入權重；Windows關閉舊連線時可能需要稍候才能重新保留連接埠。

既有模擬與本輪回歸保留原始程式、失敗候選、真正編譯／測資回饋，可用來整理後續訓練資料。但錯誤候選沒有直接加入SFT正解，未重新微調或啟用新Adapter。防退步只對本次所選測資有效，通過仍不證明所有輸入、解釋或真實學習成效正確。
